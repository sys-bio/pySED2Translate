# viva-tellurium and viva-copasi: no model input and no end-state model output

Repositories: viva-tellurium, viva-copasi (0.1.2).  Evidence: **read**.

* The model is configured as a string or path (`model`, `model_file`, `model_source`), fixed when the document is written.
  The steps have no input port for a model, so a simulation cannot start from a model produced by an earlier node
  (for example after a parameter change in a composite).
* The steps return trajectories only; the model's end state (as SBML or as values) is not an output.
  `TelluriumProcess.get_sbml()` exists as a method, not as a port.

Expected: an optional `model` input (SBML text) and an optional `model_out` output, or a documented alternative for
continuing a simulation from the end of another.

Environment: Python 3.13, process-bigraph 1.8.5, bigraph-schema 1.7.0, numpy 2.5.3; Linux (x86_64). Observed 2026-10-09.

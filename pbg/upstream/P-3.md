# process-bigraph: when does a process with a longer interval read the state?

Repository: vivarium-collective/process-bigraph (1.8.5).  Type: question, not a bug.  Evidence: confirmed by running; the
specification text is ambiguous.

The formal rule (Supplement 1, 3.8.2, "Process Update") reads a process's inputs at the event time t* at which it is due.
The implementation (`Composite.run`, with the per-process "stash" of S1 3.8.6) reads the inputs at the **start** of the
process's interval and applies the result at its end.  The two agree when all intervals are equal and differ otherwise.

Example (x' = x + 0.5 (y - x), y' = y + 0.25 (x - y), start x = 1, y = 0; p1 with interval 1 updates x, p2 with interval 2
updates y; the update functions return deltas):

| t | implementation (read at start of interval) | formal rule read at event time |
|---|---|---|
| 0 | x 1.0, y 0.0 | x 1.0, y 0.0 |
| 1 | x 0.5, y 0.0 | x 0.5, y 0.0 |
| 2 | x 0.25, y 0.25 | x 0.25, y 0.125 |
| 4 | x 0.25, y 0.25 | x 0.15625, y 0.140625 |

(Both columns were computed by independent scripts; the first matches process-bigraph 1.8.5 exactly.)

Question: which is intended?  If it is the implementation's, the specification text of 3.8.2 could say so; if it is the
formal rule's, the implementation differs for any document with unequal intervals.

Environment: Python 3.13, process-bigraph 1.8.5, bigraph-schema 1.7.0, numpy 2.2.6; Linux (x86_64). Observed 2026-10-09.

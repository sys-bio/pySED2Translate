# process-bigraph: unknown keys in a process or step config are accepted silently

Repository: vivarium-collective/process-bigraph (1.8.5).  Evidence: **confirmed by running.**

Constructing a process or step with a config key that is not in its `config_schema` raises nothing and the key has no
effect.  Seen with viva-tellurium (`bogus_key`) and viva-copasi (`relative_tolerance`, `method`, `start_time`, all valid
names for other tools but unused here).  The same holds for unknown top-level keys of a composite document
(`global_time_precison` is accepted and ignored).

Reproduction:
```python
from process_bigraph import allocate_core
from viva_tellurium.processes import TelluriumUTCStep
core = allocate_core()
TelluriumUTCStep({'model': "model d; S=1; end", 'end_time': 5.0, 'n_points': 2, 'bogus_key': 1}, core=core).update({})   # no error
```

Expected: an error or a warning naming the unknown key (perhaps with a "did you mean ...?"), or an opt-in strict mode.

Environment: Python 3.13, process-bigraph 1.8.5, bigraph-schema 1.7.0, numpy 2.5.3; Linux (x86_64). Observed 2026-10-09.

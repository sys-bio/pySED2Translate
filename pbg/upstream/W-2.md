# viva-copasi: a time course cannot start at a time other than 0

Repository: vivarium-collective/viva-copasi (0.1.2).  Evidence: **confirmed by running.**

## Summary
`CopasiUTCStep.update()` and `CopasiUTCProcess.update()` call `run_time_course(start_time=0.0, ...)` with a literal 0.0.
The config has only `time` (and `n_points` / `intervals`).  A `start_time` key is accepted and ignored.

## Reproduction
```python
from process_bigraph import allocate_core
from viva_copasi.processes import CopasiUTCStep
core = allocate_core()
# decay.xml: any SBML model, for example S -> with rate 0.5*S
for extra in ({}, {'start_time': 2.0}):
    st = CopasiUTCStep({'model_source': 'decay.xml', 'time': 5.0, 'n_points': 6, **extra}, core=core)
    t = st.update({'species_counts': {}, 'species_concentrations': {}})['result']['time']
    print(extra, t[0], t[-1])          # both print 0.0 5.0
```

## Expected
A `start_time` (initial time) in the config, passed to `run_time_course(start_time=...)`, or an error for an unsupported key.

Environment: Python 3.13, process-bigraph 1.8.5, bigraph-schema 1.7.0, numpy 2.5.3; Linux (x86_64). Observed 2026-10-09.

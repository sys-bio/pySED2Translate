# viva-copasi: the COPASI steps use schema types that only register_copasi() registers

Repository: vivarium-collective/viva-copasi (0.1.2).  Evidence: **confirmed by running.**

## Summary
`CopasiUTCStep` declares its output as `numeric_result` and `CopasiSteadyStateStep` as `any`.  Neither is a registered type in
bigraph-schema 1.7.0.  A document that contains one of these steps cannot be loaded into a `Composite` unless the core was
prepared with `viva_copasi.composites.register_copasi(core)`; `viva_copasi.core.build_core()` (the documented "cross-repo
convention") does not register them.  The failure message does not mention the type.

## Reproduction
```python
from process_bigraph import Composite, allocate_core
from viva_copasi.core import build_core
doc = {"state": {"w": {"_type": "step", "address": "local:!viva_copasi.processes.CopasiUTCStep",
                       "config": {"model_source": "decay.xml", "time": 5.0, "n_points": 6},
                       "inputs": {"species_concentrations": ["a"], "species_counts": ["b"]},
                       "outputs": {"result": ["r"]}}}}
Composite(doc, core=build_core())
# TypeError: 'str' object does not support item assignment      (bigraph_schema/core.py, append_link_path)
from viva_copasi.composites import register_copasi
Composite(doc, core=register_copasi(allocate_core()))          # works
```

## Expected
Either `build_core()` registers the two types too, or the step declares types that exist (`map[list]`, `tree`), or the error
names the unknown type.

Environment: Python 3.13, process-bigraph 1.8.5, bigraph-schema 1.7.0, numpy 2.5.3; Linux (x86_64). Observed 2026-10-09.

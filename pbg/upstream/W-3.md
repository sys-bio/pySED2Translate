# viva-copasi: no way to choose the method or tolerances; such config keys are accepted and ignored

Repository: vivarium-collective/viva-copasi (0.1.2).  Evidence: **confirmed by running.**

## Summary
The config of `CopasiUTCStep`, `CopasiUTCProcess` and `CopasiSteadyStateStep` has no method, tolerance or step-size
settings; `run_time_course` and `run_steadystate` are called with basico's defaults.  Keys such as `relative_tolerance` or
`method` are accepted without complaint and have no effect.

## Reproduction
```python
from process_bigraph import allocate_core
from viva_copasi.processes import CopasiUTCStep
core = allocate_core()
for extra in ({}, {'relative_tolerance': 1e-3}, {'method': 'stochastic'}):
    st = CopasiUTCStep({'model_source': 'decay.xml', 'time': 5.0, 'n_points': 6, **extra}, core=core)
    r = st.update({'species_counts': {}, 'species_concentrations': {}})['result']
    print(extra, len(r['time']), 'rows')       # all three run; none of the extra keys is used
```

## Expected
Optional `method` (name or KiSAO id) and `settings` (tolerances, maximum steps, ...) passed to basico's
`set_scan_settings` / `run_time_course(method=..., settings=...)`; unknown keys rejected.

## Why it matters
Simulation experiments specify the algorithm and its tolerances; without them COPASI results cannot be compared at a
stated accuracy.

Environment: Python 3.13, process-bigraph 1.8.5, bigraph-schema 1.7.0, numpy 2.2.6; Linux (x86_64). Observed 2026-10-09.
